## Что это

MemoRizz — Python-фреймворк для агентов, в котором память стоит в центре. Автор — Richmond Alake: раньше developer advocate в MongoDB, сейчас Director of AI Developer Experience в Oracle; вместе с Oracle ведёт курс DeepLearning.AI «Agent Memory» [доки]. На GitHub 782 звезды, 87 форков, проект создан в сентябре 2024. Релизы выходят почти ежедневно, последний v0.17.24 от 2026-11-06. По сути автор один (261 коммит против 4 у второго участника). Python-кода около 195 тыс. строк, много коммитов с пометкой «Co-Authored-By: Claude» [код].

**Лицензия — PolyForm Noncommercial 1.0.0.** Это не open source: коммерческое использование запрещено. Код в tessar переносить нельзя, можно брать только идеи.

Охват очень широкий: веб-интерфейс, MetaHarness (запуск задач через Codex и Claude Code), управление компьютером, дообучение моделей, плагины для Claude Code и Codex. Ядро памяти на этом фоне тонкое.

## Архитектура вкратце

- **Типы памяти** [код, `enums/memory_type.py`]: 13 хранилищ — knowledge_base, entity_memory, personas, conversation, summaries, toolbox, workflow, skillbox, semantic_cache, shared и другие. Бэкенды: файлы (JSON на запись плюс FAISS), MongoDB, Oracle, Notion.
- **Поиск** [код]: вектор выдаёт около 5 кандидатов. Дальше дедупликация, MMR и счёт по схеме Generative Agents: давность с последнего обращения, важность и релевантность, с равными весами (`memagent/utils/context_dedup.py:161`). Гибридный поиск есть только в Oracle. Слияние через RRF есть только в стенде бенчмарков.
- **Где работает LLM:** почти везде на записи. Выбор хранилища (`memagent/memory_routing.py`), извлечение фактов, оценка важности от 1 до 10, решение о дубликатах. Для этого есть «decision models»: d1, OpenAI Decisions или дообученные.
- **Обновление:** атрибут сущности перезаписывается по имени (побеждает последняя запись), в истории хранится не больше 5 прежних значений (`entity_memory.py:117`). Заметки в базе знаний изменяемы, «замещение» просто скрывает старую.
- **Время:** полей срока действия нет. Поиск по `valid_from`, `valid_to` и `as_of` в коде памяти ничего не находит [код]. Журнал изменений хранит только хеши; в доках прямо написано «Historical before/after values are not retained» (`docs/guides/memory-evolution.md`).
- **Области видимости** [код]: жёсткие стены `user_id → agent_id → memory_id → thread_id`. Есть режим `sealed`, где тред видит только себя (`retrieval.py:229`). Мягкого бонуса, как у нас, нет.
- **Забывание** [код]: оценка удержания = среднее из важности, использования и давности (`learning/retention.py:15-23`). Скрытие только с одобрения человека и обратимо. Закреплённое, проверенное и процитированное другими записями защищено.
- **Оценка:** есть стенды для LongMemEval, LongMemEval-V2, LoCoMo-Plus, BEAM и MemBench, но цифры — дымовые прогоны. LongMemEval-V2: 1 вопрос из 1. MemBench: 4 из 4. BEAM 128K: один разговор, Recall@8 0.511 (`docs/evaluation-suite.md:414-438`). Авторы сами пишут, что с опубликованными результатами это не сравнимо. Сравнимых чисел нет.

## Самое полезное для tessar

1. **Факт держится на дословной цитате** [код, `learning/consolidation.py:1263-1322`]. Извлечённый факт отбрасывается, если в нём нет поля `evidence`, которое дословно входит в текст пользователя. Ещё одно условие: слова значения должны пересекаться со словами цитаты. Промпт: `memagent/memory_routing.py:474-506`.
   - Для нас: у `remember` можно сделать необязательный `evidence`, а ядро проверит без LLM, что это подстрока эпизода.
   - Это дешёвая защита для H5 (агент пишет факты сам) и для объяснимости (П6). Долю проверенных цитат можно мерить на пути А.

2. **Таксономия отношений «новое против старого»** [код, `decision_models.py:796-822`]. Классы `same / refines / contradicts / complements / unrelated` переходят в действия `skip / update / supersede / link / insert`.
   - Это готовая разметка для H3 (правило против LLM). Наши «изменение» и «исправление» ложатся внутрь `contradicts`.
   - Готовые тест-кейсы: «два противоречащих факта без более нового — остаются оба» (`tests/unit/test_memory_consolidation.py:437`) и «один человек под двумя именами сливается только при общих фактах» (`:448`).

3. **Минимакс по кандидатам ломает слияние по баллам** [код, коммиты 5cd6299 и 8a248b0 от 2026-11-01; `context_dedup.py:73-81, 331-363`].
   - Записи с разницей в миллисекунды растягивались на весь диапазон 0..1. В итоге порядок записи решал ранжирование, и лучшее совпадение выпадало.
   - Их починка: доля диапазона пропорциональна абсолютному разбросу (меньше часа — только часть).
   - Релевантность до сих пор нормируется простым минимаксом (`:405`).
   - Для нас: когда перейдём к слиянию по баллам, не нормировать внутри набора кандидатов. Тест-кейсы можно перенести по названиям из `tests/unit/test_retrieval_scoring.py:196-292`.

4. **Независимое подтверждение E8 и нормировка RRF** [код, `benchmarks/memory_suite/retrieval.py:17-29, 160-218`].
   - Их веса после подбора: смысл 1.0, слова 0.35, сущности 0.05, время 0.05. Слова у них тоже приходится сильно приглушать. Но подбирали на дымовых наборах, так что это не доказательство.
   - Полезные приёмы:
     - RRF делится на максимально возможное значение и попадает в [0,1]. Тогда аддитивные бонусы, в том числе наш бонус пространства, выражены в понятных единицах.
     - Каналы от вариантов запроса сводятся по максимуму, а не по сумме. Документ, найденный пятью перефразировками, не получает пятикратный вес.
   - Отдельно стоит взять «oracle reader lane»: читателю дают эталонные доказательства, чтобы отделить промах поиска от промаха читателя. Это пригодится на пути А.

5. **Отбор в контекст с журналом причин** [код, `context_dedup.py:759-1089`]. Каждый кандидат получает причину отказа или выбора:
   - `already_in_history` — уже есть в окне разговора, дословно или как подстрока;
   - `exact_duplicate` и `near_duplicate`;
   - `budget_exceeded` — бюджет символов, обрезок короче 120 символов выбрасывается;
   - `mmr_selected` — выбран.

   Вывод идёт от старого к новому. Это почти готовая спецификация для хука `UserPromptSubmit` («без повторов показанного») и для объяснений.

6. **Подтверждённое пользователем не перекрывается выведенным, забывание по источнику** [код, `entity_memory.py:259` (`pinned`), `:939-1094`].
   - Закреплённое значение заменяет только закреплённая запись.
   - `forget_thread` и `forget_sources` возвращают самое новое значение из другого источника.
   - Для нас это одно правило в детерминированном замещении: `inferred` не закрывает `asserted`. Плюс операция «отозвать эпизод» с пересчётом текущей версии. В журнале событий это делается естественнее, чем у них.

7. **Их плагин для Claude Code — наш прямой конкурент** [код, `plugins/claude-code/memorizz/hooks/hooks.json`, `cli/plugin_commands.py`].
   - Хуки: SessionStart (последняя сводка плюс новейшие факты), UserPromptSubmit (по умолчанию выключен), Stop (сохраняет реплику в отдельном процессе), PreCompact и SessionEnd (сводка сессии).
   - Подкладка по промпту (`:392-450`): фиксированная квота, 4 факта проекта и 2 из `personal`. Порога нет, проверки «этого нет в памяти» нет. Это ровно тот шум, о котором предупреждает H8.
   - Id памяти — хеш абсолютного пути git-корня (`:89-104`). Значит, у worktree и второго клона одного репозитория разная память. Нам стоит сопоставлять по `git rev-parse --git-common-dir` или по remote.
   - **Код и доки расходятся:** скилл велит класть общие предпочтения в `user-preferences` (`skills/memorizz-memory/SKILL.md:56`), а хуки читают только проект и `personal` (`mcp_server/config.py:27`). То, что агент сохранит по инструкции скилла, само никогда не всплывёт.

## Что не копировать

- **Схема Generative Agents в ранжировании, плюс показ считается подкреплением** (`memagent/core.py:14599-14660`, `memory_provider/base.py:1192-1239`). Это петля самоусиления, которую наш дизайн прямо запрещает. Релевантность весит всего треть. Каждое чтение превращается в запись основной записи, причём через неатомарное «прочитать-изменить-записать», и счётчики теряются при конкурентном доступе. У нас тепло растёт только от полезности и лежит в побочной таблице — так и оставить.
- **LLM в пути записи** (маршрутизация, извлечение, важность, дубли). Это П5 и недетерминированность.
- **Изменяемые записи и журнал из одних хешей.** Нет ответа на «что было верно на момент T», нет `as_of`, история урезана до 5 значений. Наше главное отличие (H1, П1–П2) остаётся в силе.
- **Регулярки «концептов»** в `retrieval_concepts.py`. Они только английские и подогнаны под LoCoMo-Plus («capacity», «boundaries»). Это переобучение под бенчмарк.
- **Один вектор на всю сущность** (`entity_memory.py:2258`). Поиск получается грубым, а большие сущности упираются в лимит входа модели — им пришлось вводить статус `partial`.
- **Жёсткие стены вместо мягкого бонуса.** Наш E7 показывает, что стена проигрывает.

## Вердикт

Как архитектурный ориентир проект не годится: это широкий фреймворк, а не точный движок памяти. Времени, версий и сравнимых замеров в нём нет. **Брать идеи стоит, код — нельзя** из-за лицензии.

- **Заимствовать сейчас:** проверку цитаты (п. 1), таксономию отношений как разметку для H3 (п. 2), отбор с журналом причин для хука (п. 5), правило «закреплённое не перекрывается выведенным» и отзыв эпизода (п. 6).
- **Иметь в виду при слиянии по баллам:** ловушку минимакса и нормировку RRF (пп. 3–4).
- **Следить поверхностно:** как за конкурентом в нише плагинов для Claude Code и Codex (п. 7).
